`getPixelIndex` returns the offset of a pixel's first byte in `image.bitmap.data`.
Use it when you read or write the raw bytes of individual pixels, especially near the edges, where its edge handling decides what happens to coordinates outside the image.

## Signature

```ts title="getPixelIndex.d.ts"
image.getPixelIndex(x: number, y: number, edgeHandling?: Edge): number
```

`getPixelIndex` only computes a number; it doesn't read or change the image.

## Parameters

| Parameter      | Type     | Default       | Description                                                                         |
| -------------- | -------- | ------------- | ----------------------------------------------------------------------------------- |
| `x`            | `number` | required      | Column, counted from `0` at the left edge.                                          |
| `y`            | `number` | required      | Row, counted from `0` at the top edge.                                              |
| `edgeHandling` | `Edge`   | `1` (EXTEND)  | What to do with coordinates outside the image. See [Edge handling](#edge-handling). |

The pixel's red, green, blue and alpha bytes are at the returned index and the three after it.
Inside the image the index is always `(y * image.width + x) * 4`.

## Example

```ts title="example.ts"
import { Jimp } from "jimp";

const image = await Jimp.read("photo.png");
const { data } = image.bitmap;

const idx = image.getPixelIndex(10, 20);

const red = data[idx];
const green = data[idx + 1];
const blue = data[idx + 2];
const alpha = data[idx + 3];

data[idx + 3] = 128; // make the pixel half transparent
```

## Edge handling

The third argument says what to do when `x` or `y` is outside the image.
It takes a value of the [`Edge`](/jimp/concepts/constants/#edge) enum:

| Value | Name          | Coordinates outside the image                                                            |
| ----- | ------------- | ---------------------------------------------------------------------------------------- |
| `1`   | `Edge.EXTEND` | Clamped to the nearest edge pixel. The default.                                          |
| `2`   | `Edge.WRAP`   | Wrapped around to the other side, as if the image were tiled.                           |
| `3`   | `Edge.CROP`   | Not clamped: the result is `-1`, so you can skip the pixel or treat it as transparent. |

```ts title="example.ts"
const image = new Jimp({ width: 3, height: 2 });

image.getPixelIndex(1, 1); // 16
image.getPixelIndex(-1, 0); // 0, clamped to (0, 0)
image.getPixelIndex(-1, 0, 2); // 8, wrapped to (2, 0)
image.getPixelIndex(-1, 0, 3); // -1, outside the image
```

<Aside type="note" title="Edge is a type-only export">
  `jimp` exports `Edge` as a TypeScript type, not a value, so
  `import { Edge } from "jimp"` gives you nothing to call `Edge.WRAP` on at
  run time. Pass the numbers `1`, `2` or `3`, or install `@jimp/types` and
  import the enum from there: `import { Edge } from "@jimp/types"`.
</Aside>

## Notes

- **Coordinates are rounded** to the nearest whole pixel before the index is computed.
- **`-1` means outside.** Only `Edge.CROP` and `Edge.WRAP` can return `-1`. With the default `Edge.EXTEND` the index is always inside the image (unless the image is empty).
- **`Edge.WRAP` wraps once to the left and top.** A coordinate past the right or bottom edge wraps any distance, but a negative one only wraps if it's no further out than one image width or height; beyond that the result is `-1`.
- **`0` or no value means `Edge.EXTEND`.**
- **Arguments must be numbers.** Anything else throws `x and y must be numbers`.
- [`getPixelColor`](/jimp/methods/get-pixel-color/) and [`setPixelColor`](/jimp/methods/set-pixel-color/) both use `getPixelIndex` with `Edge.EXTEND`, which is why they clamp out-of-range coordinates.
- [`scan`](/jimp/methods/scan/) and [`scanIterator`](/jimp/methods/scan-iterator/) already pass each pixel's index to you, so you rarely need `getPixelIndex` inside them.
