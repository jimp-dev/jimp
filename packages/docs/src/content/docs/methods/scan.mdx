`scan` calls your function once for every pixel, row by row from the top-left corner, passing the pixel's coordinates and its index in `image.bitmap.data`.
It's the building block for custom effects and pixel analysis: most of Jimp's built-in plugins use it.

## Signature

```ts title="scan.d.ts"
image.scan(f: (x: number, y: number, idx: number) => any): this

image.scan(
  x: number,
  y: number,
  w: number,
  h: number,
  f: (x: number, y: number, idx: number) => any,
): this
```

With one argument, `scan` visits the whole image. With five, it visits only the `w` × `h` region whose top-left corner is at `x`, `y`.
`scan` runs synchronously and returns the image, so you can chain more calls after it.

## Parameters

| Parameter | Type       | Default  | Description                                       |
| --------- | ---------- | -------- | ------------------------------------------------- |
| `x`       | `number`   | `0`          | Left edge of the region.                   |
| `y`       | `number`   | `0`          | Top edge of the region.                    |
| `w`       | `number`   | image width  | Width of the region in pixels.             |
| `h`       | `number`   | image height | Height of the region in pixels.            |
| `f`       | `function` | required     | Called with `(x, y, idx)` for every pixel. |

Give all four region values or none of them; the defaults apply when you pass only `f`.

Inside `f`, the pixel's bytes are `image.bitmap.data[idx]` (red), `[idx + 1]` (green), `[idx + 2]` (blue) and `[idx + 3]` (alpha), each from `0` to `255`.
Change them to change the pixel.

## Example

Swap the red and blue channels of every pixel:

```ts title="example.ts"
import { Jimp } from "jimp";

const image = await Jimp.read("photo.png");

image.scan((x, y, idx) => {
  const { data } = image.bitmap;
  const red = data[idx];
  data[idx] = data[idx + 2];
  data[idx + 2] = red;
});

await image.write("swapped.png");
```

### Scan a region

Pass the region before the function. This makes a 100 × 50 block, starting at `(20, 10)`, half transparent:

```ts title="example.ts"
image.scan(20, 10, 100, 50, (x, y, idx) => {
  image.bitmap.data[idx + 3] = Math.round(image.bitmap.data[idx + 3] / 2);
});
```

### Collect information

`scan` doesn't have to change anything. This computes the average color of the opaque pixels:

```ts title="example.ts"
let r = 0, g = 0, b = 0, count = 0;

image.scan((x, y, idx) => {
  const { data } = image.bitmap;
  if (data[idx + 3] === 255) {
    r += data[idx];
    g += data[idx + 1];
    b += data[idx + 2];
    count++;
  }
});

const average = count ? { r: r / count, g: g / count, b: b / count } : null;
```

### Use `x` and `y`

The coordinates let an effect depend on position. This fades the image out toward the left edge:

```ts title="example.ts"
image.scan((x, y, idx) => {
  const { data } = image.bitmap;
  data[idx + 3] = Math.round(data[idx + 3] * (x / image.width));
});
```

## Notes

- **`this` is the image** when `f` is a regular `function`, as in v0: `function (x, y, idx) { this.bitmap.data[idx] = 0; }`. Arrow functions keep their own `this`, so refer to the image by name.
- **Values wrap, they don't clamp.** `bitmap.data` is a `Buffer`, so assigning `300` stores `44` and `-1` stores `255`. Clamp computed values with [`limit255`](/jimp/methods/limit255/) and round fractions yourself; fractional values are truncated.
- **You can't stop early.** The return value of `f` is ignored. To stop at the first match, use [`scanIterator`](/jimp/methods/scan-iterator/) with `break`.
- **Region values are rounded** to whole pixels.
- **Missing arguments** in the five-argument form throw `y must be a number`, `w must be a number`, `h must be a number` or `cb must be a function`.
- **Speed.** `scan` is much faster than calling [`getPixelColor`](/jimp/methods/get-pixel-color/) and [`setPixelColor`](/jimp/methods/set-pixel-color/) for every pixel. A plain `for` loop over `image.bitmap.data` in steps of 4 is faster still, if you don't need `x` and `y`.

<Aside type="caution" title="Keep the region inside the image">
  `scan` doesn't clip the region to the image. Pixels past the right edge get
  the indexes of the start of the next row, pixels left of the image get the
  end of the previous row, and pixels above or below the image get indexes
  outside the buffer, where reads return `undefined` and writes do nothing. Clamp the region first, for example
  `w = Math.min(w, image.width - x)`.
</Aside>
