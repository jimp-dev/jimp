`getPixelColor` returns the color of the pixel at `x`, `y` as a single number in `0xRRGGBBAA` form.
Use it to sample a color, check a pixel's transparency or compare a few points; pass the result to [`intToRGBA`](/jimp/methods/int-to-rgba/) to get the separate channels.

## Signature

```ts title="getPixelColor.d.ts"
image.getPixelColor(x: number, y: number): number
```

`getPixelColor` only reads the image. It returns the color, so it can't be chained.

## Parameters

| Parameter | Type     | Default  | Description                                       |
| --------- | -------- | -------- | ------------------------------------------------- |
| `x`       | `number` | required | Column, counted from `0` at the left edge.        |
| `y`       | `number` | required | Row, counted from `0` at the top edge.            |

The return value is an unsigned 32-bit integer from `0x00000000` to `0xffffffff`: one byte each for red, green, blue and alpha, in that order.

## Example

```ts title="example.ts"
import { Jimp, intToRGBA } from "jimp";

const image = await Jimp.read("photo.png");

const color = image.getPixelColor(10, 20); // e.g. 0x2f2f92e3

const { r, g, b, a } = intToRGBA(color); // { r: 47, g: 47, b: 146, a: 227 }
```

### Show the color as hex

The number prints in decimal by default.
Pad it to eight hex digits to get a CSS-style `#rrggbbaa` string:

```ts title="example.ts"
const hex = "#" + image.getPixelColor(10, 20).toString(16).padStart(8, "0");
// "#2f2f92e3"
```

### Check whether a pixel is transparent

The alpha channel is the lowest byte, so `color & 0xff` is the pixel's alpha:

```ts title="example.ts"
const isTransparent = (image.getPixelColor(0, 0) & 0xff) === 0;
```

## Notes

- **Coordinates are rounded** to the nearest whole pixel, so `getPixelColor(10.4, 19.6)` reads pixel `(10, 20)`.
- **Out-of-range coordinates don't throw.** They're clamped to the nearest edge pixel (the [`Edge.EXTEND`](/jimp/methods/get-pixel-index/#edge-handling) behavior of `getPixelIndex`), so `getPixelColor(-5, 0)` returns the color of `(0, 0)`. Check `x` and `y` against `image.width` and `image.height` yourself if that matters.
- **Arguments must be numbers.** Anything else throws `x and y must be numbers`.
- **Reading many pixels.** Each call computes an index and reads four bytes. To process a whole image, [`scan`](/jimp/methods/scan/) and reading `image.bitmap.data` directly avoids the extra work. See [Colors and pixels](/jimp/concepts/colors-and-pixels/).
- **Changes from v0.** The optional callback argument and the `getPixelColour` alias are gone; `getPixelColor` returns the value directly.
