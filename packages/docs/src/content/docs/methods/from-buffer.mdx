`Jimp.fromBuffer` decodes the bytes of an encoded image (a PNG file, an uploaded JPEG, a response body) into a new Jimp image.
Use it when you already have the data in memory; use [`Jimp.read`](/jimp/methods/read/) to load from a path or URL.

## Signature

```ts title="fromBuffer.d.ts"
Jimp.fromBuffer(
  buffer: Buffer | ArrayBuffer,
  options?: DecodeOptions,
): Promise<Jimp>
```

`Jimp.fromBuffer` is a static method. It returns a promise for a new image.

## Parameters

| Parameter | Type                    | Default  | Description                                                                                                                                                  |
| --------- | ----------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `buffer`  | `Buffer \| ArrayBuffer` | required | The encoded image: the whole file, not raw pixels. For raw RGBA pixels use [`Jimp.fromBitmap`](/jimp/methods/from-bitmap/).                                 |
| `options` | `object`                | none     | Decode options keyed by MIME type, for example `{ "image/jpeg": { maxResolutionInMP: 200 } }`. See [Reading Large Images](/jimp/guides/reading-large-images/). |

## Example

```ts title="example.ts"
import { readFile } from "node:fs/promises";
import { Jimp } from "jimp";

const buffer = await readFile("photo.jpg");
const image = await Jimp.fromBuffer(buffer);

console.log(image.mime); // "image/jpeg"
```

### Decode a download

`fetch` gives you an `ArrayBuffer`, which `fromBuffer` accepts as is.

```ts title="example.ts"
const response = await fetch("https://example.com/cat.png");
const image = await Jimp.fromBuffer(await response.arrayBuffer());
```

### Decode an upload in the browser

A `File` from an `<input type="file">` (or any `Blob`) isn't accepted directly. Read its bytes first:

```ts title="main.ts"
import { Jimp } from "jimp";

const input = document.querySelector<HTMLInputElement>("input[type=file]")!;

input.addEventListener("change", async () => {
  const image = await Jimp.fromBuffer(await input.files![0]!.arrayBuffer());

  image.greyscale();

  document.querySelector("img")!.src = await image.getBase64("image/png");
});
```

### Pass decode options

Options are keyed by MIME type, and only the ones for the detected format reach its decoder:

```ts title="example.ts"
const image = await Jimp.fromBuffer(buffer, {
  "image/jpeg": { maxResolutionInMP: 200, maxMemoryUsageInMB: 1024 },
  "image/png": { checkCRC: false },
});
```

## Notes

- **The format is detected from the data.** Jimp reads the file's signature with [file-type](https://www.npmjs.com/package/file-type), then picks the matching format. The MIME type is stored on `image.mime`.
- **EXIF orientation is applied.** JPEGs with an EXIF orientation are rotated upright, and their EXIF data is kept for [`getBuffer`'s `exif` option](/jimp/methods/get-buffer/#options). See [EXIF](/jimp/guides/exif/).
- **Errors.** Data whose format can't be recognized throws `Could not find MIME for Buffer`. A recognized format with no decoder in your Jimp throws, for example, `Mime type image/webp does not support decoding`; add the format with a [custom Jimp](/jimp/guides/webp/). Decoders throw their own errors for corrupt data and for images over a size limit.

<Aside type="caution" title="Buffer or ArrayBuffer only">
  A plain `Uint8Array` isn't converted: it reaches the decoder as is and fails
  with an error such as `data.readUInt32BE is not a function`. Pass its
  `ArrayBuffer` instead, for example
  `u8.buffer.slice(u8.byteOffset, u8.byteOffset + u8.byteLength)`.
</Aside>
