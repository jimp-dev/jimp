A pixel's red, green and blue values only describe a color once you know the color space they're in.
Most images are sRGB, which is also what viewers assume when an image doesn't say.
iPhones and many other cameras save photos in Display P3, which can show more saturated reds and greens, and embed a Display P3 ICC profile so viewers know.

Jimp keeps every image in the color space it was read in, and converts colors only where they enter or leave the image.
Images without a profile, which is most of them, are read and written exactly as before.

## Reading and writing

When [`Jimp.read`](/jimp/methods/read/) or [`Jimp.fromBuffer`](/jimp/methods/from-buffer/) loads a JPEG, PNG or WebP with an ICC profile, Jimp keeps the profile, and the pixels stay as they are.
JPEG, PNG and WebP output gets the same profile, byte for byte, so the image looks the same as the original.

```ts title="example.ts"
import { Jimp } from "jimp";

const image = await Jimp.read("iphone-photo.jpg");

image.colorSpace; // "display-p3"

image.resize({ w: 2000 });

await image.write("small.jpg"); // still Display P3
await image.write("small.png"); // also Display P3
```

`image.colorSpace` is:

- `"srgb"` for images without a profile, or with an sRGB one
- `"display-p3"` for images with a Display P3 profile, from any vendor
- `"custom"` for any other profile, such as Adobe RGB

[`clone`](/jimp/methods/clone/) keeps the color space.
JPEG 2000 files from [`@jimp/wasm-jpeg2000`](/jimp/guides/webp/#jpeg-2000) have their profile read too.

### Formats without a profile

GIF, BMP, TIFF, ICO, AVIF and JPEG 2000 output can't carry a profile in Jimp, so for those Jimp writes a copy of the image converted to sRGB.
The image itself isn't changed.

To write sRGB without a profile in a JPEG, PNG or WebP, pass `icc: false` to [`write`](/jimp/methods/write/) or [`getBuffer`](/jimp/methods/get-buffer/).
Jimp converts the colors first, so the output still looks right in every viewer.
Display P3 colors more saturated than sRGB can show are clipped.

```ts title="example.ts"
await image.write("small.jpg", { icc: false });
// or
const buffer = await image.getBuffer("image/png", { icc: false });
```

## Converting

[`image.toColorSpace()`](/jimp/methods/to-color-space/) converts the pixels and changes the profile to match:

```ts title="example.ts"
const image = await Jimp.read("iphone-photo.jpg");

image.toColorSpace("srgb"); // for example, for image recognition that expects sRGB

image.colorSpace; // "srgb"
image.iccProfile; // undefined
```

You can convert to `"srgb"` or `"display-p3"`, from either of them or from any `"custom"` RGB profile made of primaries and tone curves, which covers Adobe RGB, ProPhoto RGB and Rec. 2020.
Jimp can't convert from profiles built on lookup tables, or from CMYK, and throws if you try.
Converting to a smaller space clips the colors it can't show.

## Creating Display P3 images

Pass `colorSpace` when creating an image with [`new Jimp()`](/jimp/methods/new-jimp/#a-display-p3-canvas):

```ts title="example.ts"
const image = new Jimp({
  width: 256,
  height: 256,
  color: "color(display-p3 1 0 0)", // the most saturated red Display P3 can show
  colorSpace: "display-p3",
});

await image.write("red.png"); // with a Display P3 profile
```

[`Jimp.fromBitmap`](/jimp/methods/from-bitmap/) takes `colorSpace` too, for pixel data that's already in Display P3.

## Colors

CSS color strings mean the same as in a browser:

- `#ff0000`, `rgb()`, `hsl()` and named colors are sRGB. On a Display P3 image Jimp converts them, so `#ff0000` becomes `rgb(234, 51, 35)` in Display P3, the same red you'd see in a browser.
- `color(display-p3 r g b)` is a Display P3 color, with channels from 0 to 1 (or percentages) and an optional `/ alpha`. On an sRGB image it's converted, and clipped if sRGB can't show it.
- `color(srgb r g b)` is an sRGB color, like `#rrggbb`.

This applies to the `color` option of `new Jimp()`, to [`border()`](/jimp/methods/border/) and [`boxShadow()`](/jimp/methods/box-shadow/) colors, and to CSS colors in [`color()`](/jimp/methods/color/)'s `mix` and `xor` actions.
[`cssColorToHex`](/jimp/methods/css-color-to-hex/#color-spaces) does the same conversion when you pass it a color space.

Numbers such as `0xff0000ff` are pixel values, so they're used as they are, in the image's own color space.
The same goes for [`setPixelColor`](/jimp/methods/set-pixel-color/), [`getPixelColor`](/jimp/methods/get-pixel-color/), the background color and the `{ r, g, b }` colors of `color()`'s `mix` and `xor`.
On a Display P3 image `0xff0000ff` is Display P3's most saturated red.

## Drawing one image onto another

[`composite()`](/jimp/methods/composite/) and [`blit()`](/jimp/methods/blit/) convert the source image to the color space of the image you draw onto, so an sRGB logo keeps its colors on a Display P3 photo.
The source image itself isn't changed.

```ts title="example.ts"
const photo = await Jimp.read("iphone-photo.jpg"); // Display P3
const logo = await Jimp.read("logo.png"); // sRGB

photo.composite(logo, 10, 10);
```

<Aside type="caution" title="Draw onto the image whose space you want">
  A new image from `new Jimp()` is sRGB unless you pass `colorSpace`, so
  drawing a Display P3 photo onto one converts the photo to sRGB and clips its
  most saturated colors. Create the canvas with `colorSpace: "display-p3"` to
  keep them.
</Aside>

## Pixel operations

Operations such as [`resize()`](/jimp/methods/resize/), [`blur()`](/jimp/methods/blur/), [`brightness()`](/jimp/methods/brightness/), [`greyscale()`](/jimp/methods/greyscale/) and the `color()` adjustments work on the pixel values in the image's own color space, the same way they work on sRGB values.
White, black and grays are the same in sRGB and Display P3, so `greyscale()`, `tint()` and `shade()` give the same colors either way.
Hue and saturation changes are measured in the image's own space, so they're a little different from the same change on the sRGB version of the image.

## Removing the profile without converting

`image.iccProfile` holds the profile bytes.
Setting it to `undefined` makes Jimp treat the pixel values as sRGB without converting them, which is what Jimp did with every image before 2.0:

```ts title="example.ts"
image.iccProfile = undefined;

image.colorSpace; // "srgb", with the same pixel values
```

Setting it to another profile's bytes re-tags the image the same way.
