If you don't want to use all the default plugins included in the `jimp` package, you can create a custom Jimp.

## Creating a custom Jimp

To create a custom Jimp, you can use the `create` function from the `jimp` package.

```ts
import { promises as fs } from "fs";

import { createJimp } from "@jimp/core";
import png from "@jimp/js-png";
import * as resize from "@jimp/plugin-resize";

const MyJimp = createJimp({
  plugins: [resize.methods],
  formats: [png],
});

const image = await MyJimp.read("test/image.png");

image.resize({ w: 100 });

await image.write("test/output.png");
```

## Using a custom Jimp outside of Node.js

Jimp's packages import `Buffer` from the [`buffer`](https://www.npmjs.com/package/buffer) package instead of relying on the Node.js global.
In Node.js, Deno, and Bun this resolves to the built-in module, and bundlers targeting the browser use the npm package.
So a custom Jimp works in browsers and in Cloudflare Workers without a `Buffer` polyfill.

### Browsers

The `jimp` package ships a pre-bundled browser build with everything it needs.
A custom Jimp is bundled by your own bundler instead, so there are a few things to know.

`@jimp/js-png` has a `browser` export condition that uses the browser build of `pngjs`.
Bundlers that target the browser (Vite, webpack, esbuild, Rollup with `@rollup/plugin-node-resolve`'s `browser: true`) pick it up automatically, so you don't need to polyfill `stream`, `zlib` or `util`.

Older versions of `@jimp/core` and the format plugins use the global `Buffer`, which browsers don't provide.
If you see `ReferenceError: Buffer is not defined`, update your Jimp packages.
If you can't update, set `globalThis.Buffer` from the [`buffer`](https://www.npmjs.com/package/buffer) package before you import Jimp.

Older versions of `@jimp/js-gif` depend on `gifwrap`, which imports `fs` for file helpers that Jimp doesn't use.
Vite logs `Module "fs" has been externalized for browser compatibility` for it, and that warning is safe to ignore.

### Cloudflare Workers

A custom Jimp works in Workers without any extra configuration.
The WASM format plugins (like `@jimp/wasm-webp`) don't currently load in Workers, though.
If other dependencies in your worker need Node.js APIs, enable the [`nodejs_compat`](https://developers.cloudflare.com/workers/runtime-apis/nodejs/) compatibility flag:

```toml title="wrangler.toml"
compatibility_flags = ["nodejs_compat"]
```
