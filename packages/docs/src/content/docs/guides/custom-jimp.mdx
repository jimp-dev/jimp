title: Custom Jimp
description: How to create a custom Jimp
---

If you don't want to use all the default plugins included in the `jimp` package, you can create a custom Jimp.

## Creating a custom Jimp

To create a custom Jimp, you can use the `create` function from the `jimp` package.

```ts
import { promises as fs } from "fs";

import { createJimp } from "@jimp/core";
import png from "@jimp/js-png";
import * as resize from "@jimp/plugin-resize";

const MyJimp = createJimp({
  plugins: [resize.methods],
  formats: [png],
});

const image = await MyJimp.read("test/image.png");

image.resize({ w: 100 });

await image.write("test/output.png");
```

## Using a custom Jimp in the browser

The `jimp` package ships a pre-bundled browser build with everything it needs.
A custom Jimp is bundled by your own bundler instead, so there are a few things to know.

`@jimp/js-png` has a `browser` export condition that uses the browser build of `pngjs`.
Bundlers that target the browser (Vite, webpack, esbuild, Rollup with `@rollup/plugin-node-resolve`'s `browser: true`) pick it up automatically, so you don't need to polyfill `stream`, `zlib` or `util`.

`@jimp/core` and the format plugins use `Buffer`, which browsers don't provide.
Make the [`buffer`](https://www.npmjs.com/package/buffer) package available as a global before you import Jimp:

```ts
// buffer-global.ts
import { Buffer } from "buffer";

globalThis.Buffer = Buffer;
```

```ts
import "./buffer-global";

import { createJimp } from "@jimp/core";
import png from "@jimp/js-png";

const MyJimp = createJimp({ formats: [png] });
```

`@jimp/js-gif` depends on `gifwrap`, which imports `fs` for file helpers that Jimp doesn't use.
Vite logs `Module "fs" has been externalized for browser compatibility` for it, and that warning is safe to ignore.
