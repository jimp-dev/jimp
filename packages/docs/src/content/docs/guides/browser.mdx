Jimp comes with a pre-bundled browser version.

## Usage

There are a few main ways to use Jimp in the browser.
### From a CDN

The browser build at `dist/browser/index.js` is a self-contained ES module, so you can import it straight from a CDN without a bundler.

```html
<script type="module">
  import { Jimp } from "https://cdn.jsdelivr.net/npm/jimp@1/dist/browser/index.js";

  const image = await Jimp.read("/some/url");

  image.greyscale();

  document.querySelector("img").src = await image.getBase64("image/png");
</script>
```

The same file is on unpkg at `https://unpkg.com/jimp@1/dist/browser/index.js`.
`jimp@1` always loads the latest v1 release. Pin an exact version such as `jimp@1.7.0` to make sure an update never changes your page.

The `jimp/fonts` export isn't self-contained, so it can't be imported from a CDN.
Load your fonts by URL with `loadFont` instead (see [Using Fonts](#using-fonts)).


### With hosted file

You can initialize a Jimp instance from a URL or a file path.

```ts
import { Jimp } from "jimp";

// Read a file hosted on the same domain
const image1 = await Jimp.read("/some/url");

// Read a file hosted on a different domain
const image2 = await Jimp.read("https://some.other.domain/some/url");
```

### With uploaded files

Or you can use Jimp with an `ArrayBuffer`.
Here we take a user's uploaded image and modify it to greyscale.

```ts
function handleFile(e: React.ChangeEvent<HTMLInputElement>) {
  const reader = new FileReader();

  reader.onload = async (e) => {
    const image = await Jimp.fromBuffer(e.target?.result);

    image.greyscale();

    const base64 = await image.getBase64("image/jpeg");
  };

  reader.readAsArrayBuffer(e.target.files[0]);
}

input.addEventListener("change", handleFile);
```

### Using Canvas

You can also use Jimp with a canvas.

```ts
const canvas = document.getElementById("my-canvas");
const ctx = canvas.getContext("2d");

// Load the canvas into a Jimp instance
const image = await Jimp.fromBitmap(
  ctx.getImageData(0, 0, canvas.width, canvas.height)
);

// Manipulate the image
image.greyscale();

const imageData = new ImageData(
  new Uint8ClampedArray(image.bitmap.data),
  image.bitmap.width,
  image.bitmap.height
);

// Write back to the canvas
ctx.putImageData(imageData, 0, 0);
```

### From a data URL

`Jimp.read` accepts a data URL, so there's no need to convert it to a `Buffer` first.

```ts
const image = await Jimp.read("data:image/png;base64,iVBORw0KGgo...");
```

## Decoding faster

Jimp's default PNG and JPEG decoders (pngjs and jpeg-js) are written in plain JavaScript.
They're much slower than the decoders built into the browser.
For example, on a fast laptop, a 3072×512 PNG takes Jimp around 150 ms to decode in Chrome, and a 12 megapixel JPEG takes about a second.
If decoding is too slow for you, there are two faster options.

### WASM decoders

The WASM format plugins wrap native codecs compiled to WebAssembly.
In Chrome they decode PNGs about 3× faster than the default decoders, and JPEGs 4–6× faster.
Put them before `defaultFormats`, since Jimp uses the first format that matches an image's type:

```ts
import { createJimp } from "@jimp/core";
import { defaultFormats, defaultPlugins } from "jimp";
import png from "@jimp/wasm-png";
import jpeg from "@jimp/wasm-jpeg";
import webp from "@jimp/wasm-webp";

const Jimp = createJimp({
  formats: [png, jpeg, webp, ...defaultFormats],
  plugins: defaultPlugins,
});
```

`@jimp/wasm-webp` also lets Jimp read WebP images directly.
See [Using WEBP](/jimp/guides/webp) for how to install the plugins and set up your bundler.

### The browser's decoder

Decoding with the browser and passing the pixels to `Jimp.fromBitmap` is faster still: in Chrome, about 4× faster than the default decoders for PNGs and 8–10× faster for JPEGs.
It works for any format the browser can display, including WebP and AVIF.

```ts
async function readWithBrowser(blob: Blob) {
  const bitmap = await createImageBitmap(blob);
  const canvas = new OffscreenCanvas(bitmap.width, bitmap.height);
  const ctx = canvas.getContext("2d")!;

  ctx.drawImage(bitmap, 0, 0);
  bitmap.close();

  return Jimp.fromBitmap(ctx.getImageData(0, 0, canvas.width, canvas.height));
}

const response = await fetch("/some/image.jpg");
const image = await readWithBrowser(await response.blob());
```

The pixels might not match what Jimp's own decoders produce exactly:

- The browser converts images with an embedded color profile to sRGB.
- Canvas stores colors premultiplied by alpha, so semi-transparent pixels can be off by a little.
- The browser applies EXIF orientation itself, so the image's EXIF data isn't available to Jimp.

## Using Fonts

Jimp supports loading fonts from a URL or a file path.
You must host the fonts and will not be able to use the ones included in the node version of Jimp.

## Web Workers

Jimp can be slow and you don't want that running on the main thread.
Workers can make this experience a lot better.

First define a worker.
This is where you should import jimp and do your image transformations.

```ts
import { Jimp, loadFont } from "jimp";

// eslint-disable-next-line @typescript-eslint/no-explicit-any
const ctx: Worker = self as any;

ctx.addEventListener("message", async (e) => {
  // Initialize Jimp
  const image = await Jimp.fromBuffer(e.data.image);
  const options = e.data.options;

  // Manipulate the image
  if (options.blur) {
    image.blur(options.blur);
  }

  // Return the result
  ctx.postMessage({ base64: await image.getBase64("image/png") });
});
```

Then you can use the worker.

```ts
const fileData: ArrayBuffer = new ArrayBuffer(); // Your image data
const worker = new Worker(new URL("./jimp.worker.ts", import.meta.url), {
  type: "module",
});

worker.postMessage({
  image: fileData,
  options: {
    blur: 8
  },
});

worker.addEventListener("message", (e) => {
  setOutput(e.data.base64);
  setIsLoading(false);
});
```
