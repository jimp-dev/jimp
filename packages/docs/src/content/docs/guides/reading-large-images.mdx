Jimp decodes images with JavaScript implementations of each format and keeps every pixel in memory.
To avoid running out of memory on huge or malicious files, most decoders refuse images above a size limit.
If you need to read an image larger than the defaults, pass decode options to [`Jimp.read`](/jimp/methods/read/) or [`Jimp.fromBuffer`](/jimp/methods/from-buffer/).

## How much memory an image needs

A decoded image takes four bytes per pixel (red, green, blue and alpha), however small the file is.

| Image                      | Megapixels | Decoded size |
| -------------------------- | ---------- | ------------ |
| 1920 × 1080                | 2.1        | 8 MB         |
| 6000 × 4000 (a 24 MP photo) | 24        | 96 MB        |
| 10,000 × 10,000            | 100        | 400 MB       |

The decoder needs working memory on top of that, and every [`clone`](/jimp/methods/clone/) needs as much again.
A small, highly compressed file can still describe an enormous image, which is why the limits exist.

## Passing decode options

The second argument to `Jimp.read` and `Jimp.fromBuffer` is an object keyed by MIME type.
Jimp detects the image's type and passes only the matching options to its decoder, so you can set options for several formats at once:

```ts title="example.ts"
import { Jimp } from "jimp";

const image = await Jimp.read("huge-photo.jpg", {
  "image/jpeg": { maxResolutionInMP: 200, maxMemoryUsageInMB: 1024 },
  "image/gif": { maxResolutionInMP: 200 },
  "image/tiff": { maxResolutionInMP: 200 },
  "image/bmp": { maxResolutionInMP: 200 },
});
```

The keys and option names are typed: TypeScript only accepts options for the formats your `Jimp` class supports.

## Options by format

Resolution limits are in megapixels (width × height ÷ 1,000,000).
A 100 megapixel limit allows a 10,000 × 10,000 image.

### JPEG (`image/jpeg`)

| Option               | Default | Description                                                                                   |
| -------------------- | ------- | --------------------------------------------------------------------------------------------- |
| `maxResolutionInMP`  | `100`   | Largest image, in megapixels, that will be decoded.                                           |
| `maxMemoryUsageInMB` | `512`   | Largest amount of memory, in megabytes, the decoder may allocate.                             |
| `tolerantDecoding`   | `true`  | Decode corrupt or truncated files as far as possible instead of throwing.                     |
| `colorTransform`     | auto    | Whether to convert from YCbCr to RGB. By default this is chosen from the image's color model. |

A large JPEG can hit `maxMemoryUsageInMB` before `maxResolutionInMP`, so raise both when needed.

### GIF (`image/gif`)

| Option              | Default | Description                                                                     |
| ------------------- | ------- | ------------------------------------------------------------------------------- |
| `maxResolutionInMP` | `100`   | Largest image, in megapixels, that will be decoded. Each frame is also checked. |

### TIFF (`image/tiff`)

| Option              | Default | Description                                                                    |
| ------------------- | ------- | ------------------------------------------------------------------------------ |
| `maxResolutionInMP` | `100`   | Largest image, in megapixels, that will be decoded. Each tile is also checked. |

### BMP (`image/bmp`)

| Option              | Default | Description                                         |
| ------------------- | ------- | --------------------------------------------------- |
| `maxResolutionInMP` | `100`   | Largest image, in megapixels, that will be decoded. |

### PNG (`image/png`)

PNG has no size limit.

| Option     | Default | Description                                |
| ---------- | ------- | ------------------------------------------ |
| `checkCRC` | `true`  | Throw if a chunk's checksum doesn't match. |

### WASM formats

The [WASM format plugins](/jimp/guides/webp/) (`@jimp/wasm-avif`, `@jimp/wasm-jpeg`, `@jimp/wasm-png` and `@jimp/wasm-webp`) take no decode options, and Jimp applies no size limit to them.

## When an image is too large

When an image is over a limit, decoding throws before any pixel memory is allocated, and the promise from `Jimp.read` or `Jimp.fromBuffer` rejects:

| Format | Error message                                                                     |
| ------ | --------------------------------------------------------------------------------- |
| JPEG   | `maxResolutionInMP limit exceeded by <n>MP`                                       |
| JPEG   | `maxMemoryUsageInMB limit exceeded by at least <n>MB`                             |
| GIF    | `GIF dimensions <w>x<h> exceed the maximum resolution of <n> megapixels`          |
| TIFF   | `TIFF dimensions <w>x<h> exceed the maximum resolution of <n> megapixels`         |
| BMP    | `BMP dimensions <w>x<h> exceed the maximum resolution of <n> megapixels`          |

If your app accepts uploads, keep the defaults (or lower them) and turn the error into a friendly message:

```ts title="upload.ts"
import { Jimp } from "jimp";

async function readUpload(data: ArrayBuffer) {
  try {
    return await Jimp.fromBuffer(data, {
      "image/jpeg": { maxResolutionInMP: 40 },
      "image/gif": { maxResolutionInMP: 40 },
      "image/tiff": { maxResolutionInMP: 40 },
      "image/bmp": { maxResolutionInMP: 40 },
    });
  } catch (error) {
    if (/maxResolutionInMP|maxMemoryUsageInMB|exceed/.test((error as Error).message)) {
      throw new Error("That image is too large. Upload one under 40 megapixels.");
    }

    throw error;
  }
}
```

<Aside type="caution" title="PNG has no limit">
  PNG decoding isn't limited, so a crafted PNG can still use a lot of memory.
  If you accept untrusted uploads, check the file size before decoding, or read
  the width and height from the PNG header (bytes 16 to 23) and reject images
  that are too large.
</Aside>

## Working with large images

Once a large image is loaded, a few habits keep memory and time down:

- **Shrink early.** Call [`resize`](/jimp/methods/resize/) or [`scaleToFit`](/jimp/methods/scale-to-fit/) straight after reading, before any other method. Every later step then works on fewer pixels.
- **Clone sparingly.** Each [`clone`](/jimp/methods/clone/) copies all the pixels. Clone the small version, not the original.
- **Process one image at a time.** Running many large images through `Promise.all` holds all of them in memory at once.

See also [Reading and writing](/jimp/concepts/reading-and-writing/) for the other ways to load images, and [Errors and validation](/jimp/concepts/errors-and-validation/) for Jimp's other error messages.
