Jimp reads and writes images through format plugins: small objects that know how to decode one MIME type into pixels and encode pixels back.
The `jimp` package includes five formats written in plain JavaScript, so it runs anywhere without native code.
For WebP and AVIF, or for smaller JPEGs and PNGs, you add WASM format plugins.

## Built-in formats

These formats are in the `jimp` package and in its `defaultFormats` export:

| Format | MIME type                         | Package         | Read | Write | Transparency                                    |
| ------ | --------------------------------- | --------------- | ---- | ----- | ----------------------------------------------- |
| PNG    | `image/png`                       | `@jimp/js-png`  | yes  | yes   | Full alpha                                      |
| JPEG   | `image/jpeg`                      | `@jimp/js-jpeg` | yes  | yes   | None                                            |
| GIF    | `image/gif`                       | `@jimp/js-gif`  | yes  | yes   | On or off: only fully transparent pixels        |
| BMP    | `image/bmp`, `image/x-ms-bmp`     | `@jimp/js-bmp`  | yes  | yes   | Read from 16 and 32-bit files; never written    |
| TIFF   | `image/tiff`                      | `@jimp/js-tiff` | yes  | yes   | Full alpha                                      |

When reading, Jimp recognizes the format from the file's contents. When writing, you choose it: with a MIME type for [`getBuffer`](/jimp/methods/get-buffer/) and [`getBase64`](/jimp/methods/get-base64/), or with the file extension for [`write`](/jimp/methods/write/).

### PNG

Lossless, with full transparency. The best default for anything that isn't a photo, and for intermediate files you'll edit again.

- **Encoder and decoder:** [pngjs](https://www.npmjs.com/package/pngjs).
- **Encode options:** `colorType`, `filterType`, `deflateLevel`, `deflateStrategy`, `bitDepth` and `bgColor`. By default Jimp picks the smallest color type that loses nothing, so an opaque image is written without an alpha channel and a gray one as grayscale. See [PNG options](/jimp/methods/get-buffer/#png).
- **Decode options:** `checkCRC` (default `true`) throws when a chunk's checksum is wrong. Bytes after the end of the image, which some tools write, are ignored.

### JPEG

Lossy and small, for photos. No transparency.

- **Encoder and decoder:** [jpeg-js](https://www.npmjs.com/package/jpeg-js).
- **Encode options:** `quality`, from `1` to `100`, default `100`; and `exif`, default `false`, which writes back the EXIF data of the JPEG the image was read from. See [JPEG options](/jimp/methods/get-buffer/#jpeg).
- **Decode options:** `maxResolutionInMP` (default `100`), `maxMemoryUsageInMB` (default `512`), `tolerantDecoding` and `colorTransform`. See [Reading Large Images](/jimp/guides/reading-large-images/#jpeg-imagejpeg).
- **EXIF:** on read, Jimp parses the EXIF data and rotates the pixels to match the orientation tag. See [EXIF](/jimp/guides/exif/).
- **Damaged files:** files missing the end-of-image marker, or with stray bytes between header segments, are repaired before decoding.

### GIF

Up to 256 colors, one frame.

- **Decoder:** [omggif](https://www.npmjs.com/package/omggif). Only the first frame of an animated GIF is read.
- **Encoder:** Jimp's own. It writes a single frame. Images with 256 colors or fewer get an exact palette; others are reduced to 256 colors with Wu's quantization algorithm, without dithering. For control over the palette, call [`quantize`](/jimp/methods/quantize/) or [`dither`](/jimp/methods/dither/) first.
- **Transparency:** pixels with an alpha of `0` become transparent. Every other pixel is written as opaque.
- **Encode options:** none. Width and height can be at most 65,535.
- **Decode options:** `maxResolutionInMP` (default `100`).

### BMP

Uncompressed bitmaps, mostly for compatibility with older software.

- **Encoder and decoder:** [bmp-ts](https://www.npmjs.com/package/bmp-ts).
- **Writing:** always uncompressed 24-bit, without transparency.
- **Reading:** 1, 4, 8, 16, 24 and 32-bit files. Alpha is read from 16 and 32-bit files only.
- **Encode options:** `hr` and `vr` (resolution in pixels per meter), `reserved1` and `reserved2`. See [BMP options](/jimp/methods/get-buffer/#bmp).
- **Decode options:** `maxResolutionInMP` (default `100`).
- **Two MIME types:** `@jimp/js-bmp` registers the same encoder and decoder as `image/bmp` and as `image/x-ms-bmp` (its `msBmp` export), for code that uses the older name. Files are always read as `image/bmp`.

### TIFF

Lossless and uncompressed, used in print and scanning workflows.

- **Encoder and decoder:** [utif2](https://www.npmjs.com/package/utif2). Only the first page of a multi-page TIFF is read.
- **Writing:** uncompressed 8-bit RGBA, so files are large: 4 bytes per pixel.
- **Reading:** the common compression schemes and color models, including CMYK.
- **Encode options:** none.
- **Decode options:** `maxResolutionInMP` (default `100`).

### Transparency and `image.background`

Before encoding JPEG, BMP, GIF or TIFF, Jimp draws the image over [`image.background`](/jimp/concepts/reading-and-writing/#image-properties), which is transparent unless you set it.
For JPEG and BMP that means transparent areas turn black. Set a background color to choose what they become:

```ts title="example.ts"
image.background = 0xffffffff; // white

await image.write("on-white.jpg");
```

PNG and all the WASM formats skip this step.

## WASM format plugins

These plugins wrap codecs compiled to WebAssembly from [Squoosh](https://squoosh.app) via [jSquash](https://github.com/jamsinclair/jSquash). They aren't part of the `jimp` package. Install the ones you need along with `@jimp/core`:

<InstallCommand pkg="@jimp/core @jimp/wasm-webp" />

| Package           | MIME type    | Codec           | Read | Write | Transparency |
| ----------------- | ------------ | --------------- | ---- | ----- | ------------ |
| `@jimp/wasm-webp` | `image/webp` | libwebp         | yes  | yes   | Full alpha   |
| `@jimp/wasm-avif` | `image/avif` | libavif         | yes  | yes   | Full alpha   |
| `@jimp/wasm-jpeg` | `image/jpeg` | MozJPEG         | yes  | yes   | None         |
| `@jimp/wasm-png`  | `image/png`  | Squoosh PNG and OxiPNG | yes | yes | Full alpha |

### Adding a format

Create your own Jimp class with [`createJimp`](/jimp/guides/custom-jimp/), passing the default formats and plugins plus the new format:

```ts title="jimp.ts"
import { createJimp } from "@jimp/core";
import { defaultFormats, defaultPlugins } from "jimp";
import webp from "@jimp/wasm-webp";

export const Jimp = createJimp({
  formats: [...defaultFormats, webp],
  plugins: defaultPlugins,
});
```

```ts title="example.ts"
import { Jimp } from "./jimp";

const image = await Jimp.read("photo.webp");

await image.write("photo.png");
await image.write("small.webp", { quality: 75 });
```

The custom class has the same API, and TypeScript knows the new MIME type and its options.
The codecs are loaded the first time an image is encoded or decoded in that format, so the first call is slower.

### Replacing a built-in format

`@jimp/wasm-jpeg` and `@jimp/wasm-png` use the same MIME types as the built-in JPEG and PNG formats.
When two formats share a MIME type, Jimp uses the first one in the list, so put the WASM format **before** the defaults:

```ts title="jimp.ts"
import { createJimp } from "@jimp/core";
import { defaultFormats, defaultPlugins } from "jimp";
import jpeg from "@jimp/wasm-jpeg";

export const Jimp = createJimp({
  formats: [jpeg, ...defaultFormats],
  plugins: defaultPlugins,
});
```

With `[...defaultFormats, jpeg]`, the built-in JPEG format would still be used for reading and writing.

### Encode options

All four plugins accept `colorSpace`, `"srgb"` (default) or `"display-p3"`, which tags the output's color space. The other options are specific to each codec. Options are validated, so a value out of range throws a validation error listing the problem, for example `Too big: expected number to be <=100`.
None of the WASM plugins take decode options.
